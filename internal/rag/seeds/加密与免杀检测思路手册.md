# 加密与免杀检测思路手册

> 手册目标：攻击者用加密 Webshell、内存马、进程注入、rootkit 绕过静态检测。本手册教你从**流量特征、进程行为、内核状态**三个层面把它们挖出来。核心前提：免杀逃过静态扫描，但逃不过运行时行为与流量统计。

## 加密 Webshell 流量特征（冰蝎 / 哥斯拉 / 蚁剑）

### 冰蝎（Behinder）
- **固定特征**：
  - 请求头默认 UA 异常（`User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/... Chrome/...` 实际是 Java 环境发出，缺真实浏览器特征）
  - 客户端与服务端交互经过 **AES 加密**，默认密钥 `e45e329feb5d925b`（md5(rebeyond) 前 16 位）
  - 每次请求 `Content-Length` 与响应字节数**固定**（AES 填充导致密文长度恒定）
  - PHP 版本流量含 `eval(base64_decode(...))` 形态；JSP 版本每请求带固定 `key` 参数
- **抓包观察点**：
```bash
tcpdump -i eth0 -n -A host <web_ip> and port 80
# 特征：POST 到 .php/.jsp，响应长度恒定（多次请求对比），body 为不可读密文但长度规律
```

### 哥斯拉（Godzilla）
- **固定特征**：Payload 默认密钥与类名可识别；请求中带 `pass` 参数名（默认 `pass`）与固定 header（`User-Agent: Mozilla/5.0...` 之外会带 `Accept-Encoding: gzip, deflate` + 特定 Cookie `rememberMe=deleteMe` 混淆是常见变体）；流量含 Java 序列化特征 `aced0005` 开头。
- 抓包中多次 POST 响应首字节固定为 `d`（哥斯拉 AES 加密标志）。

### 蚁剑（AntSword）
- **固定特征**：UA 默认 `antSword/v2.1`（历史版本）/`Mozilla/5.0 (compatible; MSIE 10.0; Windows NT 6.1; Trident/6.0)`；payload 是 `@eval(base64_decode(...))`、`assert(base64_decode(...))`；请求参数包含 `xxx0=...&xxx1=...` 风格。

### 检测命令与日志关键字汇总
```bash
# access.log 中找 UA
grep -iE "antSword|Behinder|Godzilla" /var/log/nginx/access.log
# 响应长度恒定：按 (URL, 状态码, 响应字节数) 分组统计，同 URL 字节数精确一致出现多次
awk '{print $7, $9, $10}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head
# 多次 POST 到同一 php 且 body 为高熵 base64 => 高危
```
- **通用检测点**：同一 `.php/.jsp` 被反复 POST、每次响应字节数完全相同、body 熵值极高（>7.5 bits/byte）、参数名含 `pass|key`。

## 内存马检测（Java Filter / Listener / Servlet）

- **概述**：不落盘，注入到运行中 JVM 的内存，静态查目录查不到。利用后权限维持极隐蔽。
- **常见注入点**：Spring `ApplicationContext` 注册 Filter；Tomcat 的 `ContextConfig` 生命周期添加 Listener；直接注册 Servlet 到 `StandardContext`。
- **检测流程（务必在宿主机/容器外执行，不要在被检 JVM 里信任结果）**：
```bash
# 1) 先看进程与端口
ps aux | grep java
ss -antp | grep java
# 2) jmap 看 heap（检查 filter/servlet 对象）
jps -l                                     # 列出 java 进程 PID
jmap -heap <pid>                           # 堆概况
# 3) 用 arthas 在线查 Filter（推荐，覆盖内存马典型行为）
#   ./as.sh 进入后：
#   dashboard          # 看线程与类加载
#   classloader        # 查看类加载器，内存马常在自定义 loader 下
#   sc -d *Filter*     # 列出所有 Filter 类
#   memtool 反编译可疑 Filter 查看逻辑（无 web.xml 注册记录却存在）
# 4) heapdump 分析（静态稳妥）
jmap -dump:format=b,file=/tmp/heap.hprof <pid>
# 用 MAT/Arthas profiler 查 org.apache.catalina.core.ApplicationFilterChain 中异常 Filter
```
- **检测特征**：进程存在但在 `web.xml`/Spring 配置里找不到的 Filter/Listener/Servlet；类名随机/含 `payload|shell|cmd` 等关键字；`jstack` 中有监听请求的非常规线程。
- **加固建议**：Tomcat 开启 `org.apache.catalina.valves.RemoteAddrValve` 限制来源；关键服务加 WAF 层（内存马流量同样会被 WAF 识别）；升级到 Tomcat 9.0.x 最新（Servlet 注册行为更可审计）。

## 进程注入检测（CreateRemoteThread / ptrace）

### Windows 侧
- **手法**：`CreateRemoteThread`/`QueueUserAPC`/`NtWriteVirtualMemory` 注入到合法进程（explorer/svchost）。
- **检测命令**（PowerShell / Sysinternals）：
```powershell
# 所有进程的主模块是否被替换/加载了不常见 DLL
Get-Process | ForEach-Object { $_.Modules } | Select ModuleName, FileName
# Process Explorer：查看进程里 DLL 的路径，异常目录（Temp/AppData/Temp）即可疑
# 连接情况：被注入进程向外网发起连接
netstat -ano | findstr ESTABLISHED
# Sysmon Event ID 8 (CreateRemoteThread) / 10 (ProcessAccess)：非标准调用链即告警
```
- **特征**：合法进程出现高熵内存区域（`malfind` 可查）、进程向陌生 IP 外连、DLL 从 Temp 目录加载。

### Linux 侧
- **手法**：`ptrace` 附加调试注入（`gdb -p`、`shellter` 类）、`LD_PRELOAD` 劫持。
- **检测命令**：
```bash
# 禁止 ptrace（生产环境合理默认）
echo "kernel.yama.ptrace_scope = 1" >> /etc/sysctl.d/99-hardening.conf && sysctl -p
# 检查 LD_PRELOAD 环境变量与 ld.so.preload
cat /etc/ld.so.preload 2>/dev/null   # 非空则异常
cat /proc/<pid>/environ | tr '\0' '\n' | grep -i preload
lsof -p <pid> | grep -E "\.so|\.out"   # 看已加载 so 路径
# 异常 so 常位于 /tmp、/var/tmp、/dev/shm
```

## Rootkit / LKM 检测（Linux）

- **概述**：LKM rootkit 挂接 `sys_call_table` 隐藏进程/文件/连接。
- **检测命令**：
```bash
# 1) 工具（都跑一遍，结果交叉比对）
yum install -y chkrootkit rkhunter   # CentOS7 / apt 类似
chkrootkit | grep -iE "infected|suspect"
rkhunter --check --sk | grep -iE "Warning"
# 2) 内核模块比对：模块文件与加载记录不符
cat /proc/modules
lsmod
ls /lib/modules/$(uname -r)/kernel/     # 新增 .ko 且 lsmod 里没有记录
find /lib/modules -name "*.ko" -newermt "2026-08-01" 2>/dev/null
# 3) 文件/进程"双视图"对比（/proc 与磁盘 ls）
#   rootkit 会让 /proc 里隐藏指定名进程；用 ps 与 /proc/*/cmdline 遍历比对
for d in /proc/[0-9]*; do cat $d/cmdline 2>/dev/null; echo; done
# 4) 检测 hook：比较 /proc/sys 与 /proc/sys 里数值被篡改、dmesg 出现可疑模块加载
dmesg | grep -iE "hide|backdoor|rootkit|ko"
# 5) 网络连接被隐藏：ss 无显示但抓包有流量 => 强信号
```
- **加固**：`lsmod` 基线化保存（加固时记录 `lsmod > /root/modules.baseline`，赛后 diff）；内核开启 `CONFIG_MODULE_SIG_FORCE` 强制签名；启动加 `module.sig_enforce=1`。

## 文件隐藏检测（chattr / e2fsck）

- **手法**：`chattr +i` 把后门文件设不可删不可改；`chattr +a` 只允许追加；攻击者利用它防删除。
- **检测与清除**：
```bash
# 查找被设置 immutable/append 的文件（正常业务文件极少 +i）
lsattr -R /var/www/html 2>/dev/null | grep -E "\-i\-|\-a\-" | grep -v "^\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-"
lsattr /tmp /var/tmp /dev/shm -R 2>/dev/null
# 清除属性
chattr -i /path/to/shell.php
chattr -a /path/to/shell.php
rm -f /path/to/shell.php
# 若文件系统层面损坏或目录被 chattr 包裹，用 e2fsck 修复后可操作
umount /dev/sdX1 && e2fsck -y /dev/sdX1   # 谨慎操作，先取证镜像
```
- **补充手法**：文件名以 `.` 开头 + `history` 清空；`/dev/shm`、`/tmp` 下的随机目录。用 `find / -name ".*" -type f -mmin -120` 补充排查。

## 恶意加密流量识别

- **概述**：C2/隧道普遍用 TLS/AES 加密，但加密改变不了**流量统计特征**。
- **检测维度**：
  1. **连接模式**：心跳间隔恒定（见 16 号文件）；请求/响应大小固定。
  2. **TLS 指纹**：JA3/JA3S 与已知恶意工具库比对（beacon/viper 的 JA3 已收录）；证书自签名/`CN` 为随机串。
  3. **熵与长度**：`tcpdump` 导出后测 payload 熵（加密数据熵≈8）。
  4. **行为**：通信 IP 属于动态域名（`freenom`/ddns）或云厂商境外段，且无业务解释。
- **检测命令**：
```bash
# 用 tshark 抓 https 统计 SNI 与证书
tshark -r capture.pcap -Y "tls.handshake.type==1" -T fields -e tls.handshake.extensions_server_name -e tls.handshake.certificate
# 连接数 TOP IP
tshark -r capture.pcap -T fields -e ip.dst | sort | uniq -c | sort -rn | head -20
# 若已部署 Suricata/Zeek：启用 JA3 指纹日志 zeek -r pcap 生成 ssl.log 查 ja3
```
- **工具建议**：`ja3`（指纹）、`zeek`（元数据）、`suricata`（规则）、`nDPI`（加密流量分类）。
