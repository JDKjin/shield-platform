# APT 攻击链与 IOC 深度分析手册

> 从攻击链视角做深度溯源：不只看单点告警，而是还原「侦察 → 投递 → 利用 → 提权 → 持久化 → 横向 → 目标达成」全链路，提取 IOC 并形成可复用的检测清单。

## 一、攻击链七阶段与检测对照

| 阶段 | 攻击行为 | 检测/日志位置 |
|------|---------|--------------|
| 侦察 | 端口扫描、目录枚举、指纹探测 | 大量 404/短连接、access.log 扫描特征 |
| 投递 | 上传 WebShell、发送钓鱼附件、下载恶意文件 | 上传请求、`find -mmin`、tmp 新增文件 |
| 利用 | 漏洞利用（注入/反序列化/文件包含） | WAF 拦截、error.log、异常响应 |
| 提权 | SUID/内核/sudo 提权 | `find / -perm -4000` 突变、sudo 日志 |
| 持久化 | 计划任务/启动项/服务/公钥/账号 | crontab、systemd、authorized_keys、passwd |
| 横向 | 口令复用、SMB、SSH 横向 | 兄弟机来源登录、445 连接 |
| 目标达成 | 抄 flag、破坏数据、回连 C2 | 数据访问日志、异常外连 |

## 二、IOC 提取清单

```bash
# 网络 IOC
ss -tnp | grep ESTAB                        # 外连 IP:端口
tcpdump -i any -nn -s0 -w /tmp/ioc.pcap     # 抓包保存
# 域名 IOC
grep -E 'server|Host' /var/log/nginx/access.log | awk '{print $1}' | sort -u
# 文件 IOC
find / -type f -mmin -120 -exec md5sum {} \; 2>/dev/null   # hash 清单
# 进程 IOC
ps -eo pid,user,args | grep -vE '\[.*\]'
# 账号/计划任务 IOC
awk -F: '$3==0{print}' /etc/passwd; crontab -l
```

## 三、时间线重建方法

1. **收集锚点**：把所有告警、日志、文件 mtime 按时间排序，找出最早的可疑行为作为「初始访问」锚点。
2. **双向扩散**：从锚点向前找侦察痕迹，向后找后续动作（提权→持久化→横向）。
3. **交叉印证**：同一时间点，网络日志 + 系统日志 + 文件系统三路证据互证（如：注入请求时间 = 文件新增时间 = 外连建立时间）。

## 四、常见 APT 特征与隐蔽手法

| 隐蔽手法 | 特征 | 检测手段 |
|---------|------|---------|
| 进程伪装 | 进程名 `[kworker]`/`svchost`/随机串 | 对比基线进程表 |
| 无文件攻击 | PowerShell/内存执行，无落盘 | 4104 事件、进程命令行 |
| 白名单滥用 | 用 certutil/powershell 下载执行 | 命令审计 |
| 隧道隐蔽 | DNS/ICMP/HTTPS 隧道 | 大流量异常、DNS 高频率 |
| 日志清洗 | 清 access/secure、删 1102 审计 | 日志完整性校验 |
| 时间戳伪造 | touch -r 伪造文件时间 | 比对 inode 时间（ctime 不可伪造） |

## 五、输出 IOC 报告格式

| 类型 | IOC | 来源/时间 | 置信度 | 处置 |
|------|-----|----------|--------|------|
| IP | 1.2.3.4:4444 | ss 外连 10:02 | 高 | 已封 OUTPUT |
| 域名 | bad.example.com | DNS 日志 | 中 | 已封 |
| 文件 | /tmp/x (md5:...) | find -mmin | 高 | 已隔离取证 |
| 进程 | /var/tmp/xx | ps 审计 | 高 | 已 kill |
| 账号 | eviluser | passwd | 高 | 已锁定 |

## 六、复盘与检测规则固化

1. 把 IOC 写入面板/防火墙规则，同源后续行为自动告警。
2. 对「初始访问入口」做修复验证（打一遍原载荷确认已拦）。
3. 更新基线快照（进程/端口/文件 hash），下一次增量对比更快。
4. 报告按攻击链七阶段组织，附每阶段证据与时间线。
