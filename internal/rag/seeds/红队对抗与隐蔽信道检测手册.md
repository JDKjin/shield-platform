# 红队对抗与隐蔽信道检测手册

> 手册目标：把攻击者常用的代理链、隧道、C2 通信"对号入座"，给出可执行的检测命令与日志特征。核心思想：**不只看端口，要看流量内容与连接模式**。

## 代理链：frp / nps / ew

- **概述**：攻击者把受害机当作跳板，运行内网穿透工具把内网端口映射到外网，实现远程稳定控制。
- **frp 特征**：客户端默认连接服务端 7000 端口（`frps.ini`/`frpc.ini`）；进程名 `frpc/frps`；配置里常见 `[common] server_addr server_port`。
- **nps 特征**：服务端默认 8080 管理端口、8024 桥接端口；进程名 `nps/nps-server`；配置 `nps.conf`。
- **ew（EarthWorm）特征**：单文件二进制（无配置文件，纯参数运行），如 `ew -s ssocksd -l 1080`、`ew -s rcsocks -l 1080 -e 8888`。
- **检测命令**：
```bash
# 1) 进程与监听
ps aux | grep -E "frp|nps|ew|socks|kcptun"
ss -antp | grep -E "7000|8024|1080|8888"          # 常见默认端口
# 2) 异常双向长连接：与陌生 IP 保持稳定连接且流量双向对称
ss -antp | grep ESTAB | awk '$5 !~ /:22|:80|:443|:3306/'
# 3) 对比公网地址：查连接对端是云厂商 IP（阿里云/腾讯云境外）且本机无业务对应
netstat -tnp | grep ESTABLISHED
```
- **日志特征**：防火墙/IDS 日志中同 IP 长时间长连接；进程命令行含 `frpc|nps|ew -s`；历史命令 `~/.bash_history` 出现下载命令。

## SSH 隧道（-L / -R / -D）

```bash
# 本地转发 -L：把远端服务的端口带到本地
ssh -L 8080:127.0.0.1:80 user@target       # 本地 8080 -> target 的 80
# 远程转发 -R：把本地端口暴露到远端，外网可访问内网
ssh -R 2222:127.0.0.1:22 vps
# 动态转发 -D：本地 socks5 代理
ssh -D 1080 user@target
# 常见组合：-N 不执行命令 -f 后台 -o 参数绕过首次确认
ssh -CfNg -L 8080:172.16.1.10:3306 user@target
```
- **检测特征**：本机进程有 `ssh -L|-R|-D|-N|-f`；SSH 连接数量异常多（一个用户 N 个长连接）；`ss -antp | grep sshd` 对端为陌生 IP 且连接长期存在。
- **检测命令**：
```bash
# 查看 sshd 建立的隧道（登录后交互进程的 PPP 不存在，只有 sshd 长连）
ss -antp | grep sshd
# 检查 ssh 客户端进程命令行
ps aux | grep "ssh -"
# 对每台服务器限制 ssh 并发连接与 idle 超时
```

## DNS 隧道（iodine / dnscat2 特征）

- **概述**：DNS 协议出站被放行时，把数据编码进域名，与权威 DNS 服务器通信。
- **特征**：
  - 同一子域（如 `tunnel.attacker.com`）出现**大量子域名解析**，子域为高熵 Base32/hex 随机串：`d41d8cd98f00b204e9800998ecf8427e.tunnel.attacker.com`
  - 查询类型异常：TXT 记录短时间激增（iodine 常用 TXT）、解析频率远超正常
  - 单域名每秒 N 次查询（正常缓存命中率应很高）
  - dnscat2 默认子域 `dnscat.attacker.com`；iodine 默认编码 Base32
- **检测命令**：
```bash
# 抓 DNS 流量看查询名熵
tcpdump -i eth0 -n port 53
# 统计查询频率最高的域名（异常子域大量出现）
# 在 DNS server 侧：BIND querylog / dnsmasq --log-queries 抓取
# 计算子域标签熵值（高熵 => 可疑）
# 特征命中后临时阻断：防火墙仅允许白名单域名解析
```
- **日志特征**：DNS 日志中子域名长度明显超长（>30 字符）、Base32 字符集（A-Z2-7）、TX 记录暴涨。

## ICMP 隧道

- **概述**：把数据塞进 ICMP Echo/Reply 包负载（如 `ptunnel`、`icmpsh`）。
- **检测特征**：正常 ping 的 payload 是固定 32/56 字节且无业务意义；隧道数据包 payload 大小固定且异常（如固定 1024 字节）、ICMP 包数量突增、无对应 TCP 业务。
- **检测命令**：
```bash
tcpdump -i eth0 -n icmp
# 正常：icmp-seq 有规律递增、payload 固定模式
# 异常：payload 长度一致但不等于标准值，或 ICMP 速率异常（>20 pkt/s）
# 关闭 ping 响应（server）：
sysctl -w net.ipv4.icmp_echo_ignore_all=1
```

## 端口复用 / 域前置

### 端口复用
- **概述**：复用已开放的 80/443 端口，把隧道流量伪装成 HTTP/HTTPS，绕过端口白名单与防火墙。
- **检测特征**：80/443 连接中混杂非浏览器 UA 与异常 Path；连接数远超正常访问量；TLS SNI 指向可疑域名。
- **检测命令**：
```bash
ss -antp | grep -E ":80|:443" | grep ESTAB
# nginx 访问日志中 path 为随机串、UA 为恶意工具特征（见 19 号文件）的请求
# 开启 HTTPS 双向证书校验可大幅压缩复用空间
```

### 域前置（Domain Fronting）
- **概述**：用 CDN 高信誉域名（如 `www.google.com`）做 SNI，实际 Host 头指向 C2，绕过域名黑名单。
- **检测特征**：TLS 握手 SNI 与 HTTP Host 头不一致；TLS 会话对外是知名 CDN IP，但请求目标路径/Cookie 异常。
- **检测命令**：代理/防火墙支持解 TLS 时比对 `SNI != Host` 即告警；无法解 TLS 时依赖证书指纹与连接行为分析。

## C2 流量特征（Beacon 心跳与加密）

### Cobalt Strike Beacon
- **心跳特征**：固定间隔（默认 60s，可改）向 C2 发起 HTTP(S) GET/POST，请求之间间隔**恒定**（时间序列上呈精确节拍）；睡眠抖动小时钟特征明显。
- **请求特征**：
  - URL path 长度固定或为随机化变体：`/xxxxx`、`/pixel.gif`、`/__utm.gif`（伪装）
  - User-Agent 固定或少数几个（如 `Mozilla/4.0 (compatible; MSIE 7.0...)`）
  - POST 数据为加密 base64（固定密钥，`malleable C2` 改造后形态更多样）
  - 响应体大小固定、有特定填充（beacon 响应随机填充到固定长度）
- **检测命令**：
```bash
# 抓包观察心跳间隔
tcpdump -i eth0 -n host <c2_ip>
# 对同一 (src,dst,dport) 的连接做间隔分布分析，标准差 <1s 则高度可疑
# Suricata 规则：检测固定 UA + 加密 base64 的 /__utm.gif 类路径
```
- **Zeek/IDS 可加指标**：会话字节数固定、TLS 指纹（JA3）为 beacon 已知值、SNI 为动态域名。

### Meterpreter / 其他 C2
- meterpreter 默认端口 4444；stage2 传输是原始 TCP（无 HTTP 头），流量高度规律。
- 检测：`ss -antp` 中与未知 IP 的 4444/5555 连接；抓包中负载以 `\x00\x00\x00` 魔数开头的原始 TCP 流。

## WebSocket / SSH 外连异常检测

### WebSocket 外连（浏览器 JS C2 / 反弹）
```bash
# WebSocket 升级请求：HTTP Upgrade: websocket
# 服务端日志特征：Upgrade 请求 + 101 Switching Protocols 大量出现
grep -i "websocket" /var/log/nginx/access.log
# 检测点：客户端为可疑域名、连接长时间保持、消息频率规律
```

### SSH 外连异常
```bash
# 检测本机主动向外发起 SSH（正常服务器极少外连 sshd）
ss -antp | grep ":22" | grep ESTAB
# 结合命令历史：~/.bash_history 中出现 ssh -o StrictHostKeyChecking=no user@ip
# 大量认证失败（横向尝试）
grep -c "Failed password" /var/log/secure
# 相同私钥被多次尝试登录不同主机（攻击者用同一私钥横扫内网）
```

## 隐蔽信道综合检测 Checklist

- [ ] `ss -antp` 排查 ESTABLISHED 中陌生 IP 的长连接（>10min）
- [ ] `ps aux` 排查 frp/nps/ew/ssh -L-R-D/socks 相关进程
- [ ] `tcpdump -n port 53` 抽查 DNS 流量高熵子域
- [ ] 抓 ICMP 流量验证包长与频率是否异常
- [ ] 检查 80/443 连接中非浏览器 UA 与异常 path
- [ ] 对同源同宿连接做"间隔方差分析"，定位 beacon 心跳
- [ ] 全部检测结果记录 IP、端口、时间，交溯源报告
