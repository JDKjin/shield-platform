# 溯源取证深化手册

> 手册目标：从"看日志"升级为"完整取证"。覆盖内存取证、磁盘取证、日志字段、时间线重建、电子证据固定。原则：**先固定证据，再分析；先只读，再操作；全过程留痕**。

## 取证前置：电子证据固定

- **核心规则**：
  1. **只读操作**：所有取证动作在副本上做，原机尽量关机或快照。
  2. **哈希固定**：第一时间记录原文件/镜像 hash。
  3. **Chain of Custody（保管链）**：记录证据获取人、时间、工具、交接，形成书面链条。
  4. **现场时间同步**：记录系统时间与标准时间偏差。
- **操作命令**：
```bash
# 1) 关机前先采内存（见下），再做磁盘镜像
# 磁盘镜像（源设备只读挂载或 dd 前先 umount）
md5sum /dev/sda1 > evidence_hash.txt            # 记录原始 hash
dd if=/dev/sda of=/evidence/sda.img bs=4M       # 物理镜像（要避开正在写的系统分区）
# 2) 副本验证
md5sum /evidence/sda.img | tee -a evidence_hash.txt
sha256sum /evidence/sda.img | tee -a evidence_hash.txt
# 3) 只读挂载副本进行分析（禁止挂载原盘后写数据）
mkdir /mnt/evidence && mount -o ro,loop /evidence/sda.img /mnt/evidence
```
- **Windows 侧**：采集前 `shutdown /s /t 0` 前先做内存（见 Volatility）；磁盘用 FTK Imager 做 E01 镜像（记录 case number、hash）。

## 内存取证：Volatility 全流程

### Windows 内存采集与基础分析
```powershell
# 采集（在目标机执行）
# 工具：DumpIt / WinPmem（winpmem_mini_x64_rc2.exe）
.\winpmem_mini_x64.exe c:\evidence\mem.raw
# 分析机（Kali/专用取证箱）
volatility -f mem.raw imageinfo                     # 选 profile（Win7SP1x64 等）
volatility -f mem.raw --profile=Win7SP1x64 pslist   # 进程列表（不含隐藏进程）
volatility -f mem.raw --profile=Win7SP1x64 psscan   # 扫描已结束/隐藏进程（含被 rootkit 藏起的）
volatility -f mem.raw --profile=Win7SP1x64 malfind  # 找可执行内存区（注入/免杀壳特征）
volatility -f mem.raw --profile=Win7SP1x64 dlllist -p <pid>     # 进程加载的 DLL
volatility -f mem.raw --profile=Win7SP1x64 connscan  # 网络连接（比 netstat 更全，含已断）
volatility -f mem.raw --profile=Win7SP1x64 hashdump  # 抓 SAM 哈希（配合横向检测）
volatility -f mem.raw --profile=Win7SP1x64 cmdline   # 所有进程命令行（找 base64/iex）
volatility -f mem.raw --profile=Win7SP1x64 timeliner --output=csv --output-file=win_tl.csv  # 时间线
```
- **分析要点**：`malfind` 结果里 `PAGE_EXECUTE_READWRITE` 区域高度可疑；`psscan` 与 `pslist` 对比差集 = 隐藏进程；`hashdump` 结果提交哈希分析平台。

### Linux 内存采集与 Volatility 差异
```bash
# 采集（首选 LiME）
apt install -y lime-forensics
insmod lime-forensics-dkms.ko "path=/evidence/mem.lime format=lime"
# 分析：Linux 版 Volatility 3 无需 profile（自动探测）
vol3 -f mem.lime linux.pslist
vol3 -f mem.lime linux.pstree
vol3 -f mem.lime linux.bash        # 历史命令（取证重点）
vol3 -f mem.lime linux.check_creds
vol3 -f mem.lime linux.dmesg
vol3 -f mem.lime linux.malfind
vol3 -f mem.lime linux.netstat     # 内核级网络连接
```
- **Linux 差异**：没有 SAM/注册表；凭证在 `/etc/shadow`（需 hash 爆破）；重点关注 `linux.bash`、`linux.environ`（进程环境变量含 LD_PRELOAD/代理变量）、`linux.netstat`。
- **实操注意**：采集内存前**不要**运行 chkrootkit/清日志等命令（会改变内存）；先把内存采完。

## 磁盘取证：镜像与文件恢复

- **概述**：攻击者删掉的 Webshell、日志、工具会被文件系统保留（数据块未覆写）。
- **工具与命令**：
```bash
# Linux ext4：extundelete 恢复（先只读挂载，再对副本操作）
extundelete /evidence/sda.img --restore-all --restore-directory=/evidence/restore
# 精确恢复特定文件
extundelete /evidence/sda.img --restore-file var/www/html/shell.php
# Windows NTFS：TestDisk / PhotoRec（对 E01 镜像跑）
testdisk /evidence/disk.E01
# 全盘关键字扫描（删除文件内容仍残留）
grep -a -rl "<?php @eval\|Behinder\|Godzilla" /mnt/evidence/ 2>/dev/null
strings /evidence/sda.img | grep -iE "base64 -d|wget http|/etc/shadow"
```
- **时间线辅助**：恢复出的文件看 mtime/删除时间，结合攻击时间窗判断。

## 日志字段解读（auth / secure / Windows 事件）

### Linux：auth.log / secure 关键字段
```
Mar 25 03:22:17 host sshd[12345]: Failed password for root from 203.0.113.9 port 51234 ssh2
Mar 25 03:22:20 host sshd[12345]: Accepted password for root from 203.0.113.9 port 51236 ssh2
```
- **字段**：时间、主机名、服务(sshd)、PID、事件类型、用户、来源 IP、来源端口、协议版本。
- **关注点**：`Failed password`（爆破）、`Accepted` 前后紧邻（爆破成功）、`invalid user`（扫描账户）、`Connection closed by authenticating user`（撞库）。

### Windows 事件 ID 速查表

| Event ID | 含义 | 取证重点 |
|----------|------|---------|
| 4624 | 登录成功 | 看 Logon Type：3=网络 8=PTH 10=RDP；配合源 IP |
| 4625 | 登录失败 | 连续失败 = 爆破；失败后成功 = 爆破成功 |
| 4688 | 进程创建 | 命令行里 base64/iex/powershell 参数 |
| 1102 | 安全日志被清除 | 攻击者清理痕迹的铁证 |
| 7045 | 新服务安装 | 服务名 + 可执行路径在 Temp 目录 |
| 20001 | Sysmon 进程创建 | 补充 4688 的细节（父进程/命令行） |
- **查询命令**：
```powershell
Get-WinEvent -FilterHashtable @{LogName='Security';Id=4625;StartTime=(Get-Date).AddDays(-7)} | Where {$_.Properties[18].Value -notmatch "^0\.0\.0\.0"} | Group-Object {($_.Properties[18].Value)} | Sort Count -Desc
# 4688 命令行：开启审核进程创建 + commandline（本地策略或 GPO）后才有
Get-WinEvent -FilterHashtable @{LogName='Security';Id=4688} | Select TimeCreated, Message | fl
```

## 时间线重建（plaso 工具链）

- **目标**：把文件时间、日志时间、进程时间统一成一条时间线，还原攻击顺序。
- **操作**（Linux 取证箱）：
```bash
# plaso 解析器：可吃 dd 镜像/E01/文件系统
log2timeline.py /evidence/timeline.plaso /evidence/sda.img
psort.py -o l2tcsv -w /evidence/timeline.csv /evidence/timeline.plaso
# 过滤攻击窗口
head -n1 /evidence/timeline.csv
grep "2026-08-0" /evidence/timeline.csv | head -50
# 备选轻量：自动按 mtime 排序找突变
find /var/www/html -newermt "2026-08-07" -type f -printf "%T+ %p\n" | sort
```
- **工具链**：`plaso`（主）、`find -newermt`（快速）、`stat`（单文件）、Windows 侧用 `timeline explorer`/`velociraptor`。
- **时间线要素**：每行应包含 UTC 时间、源（文件/日志/注册表）、事件、对象路径。
