# 渗透测试工具与特征识别手册

> 手册目标：把 AWD 中最常出现的攻击工具"对号入座"。每项给出**工具特征 → 检测点 → 拦截建议**。攻防双方都在用这些工具，识别能力直接决定防御响应速度。

## Nmap 扫描特征

- **扫描特征**：
  - SYN 扫描（`-sS`，默认）：向目标大量发送 SYN 包，不完成三次握手；单 IP 在短时间（秒级）内访问大量不同端口/主机。
  - 常见端口序列：先探测 21/22/80/443/3306/3389/8080/7001 等 Top 端口，再扩展全端口。
  - 目标端口开放时返回 `SYN+ACK`（半连接）；关闭返回 `RST`。
  - 版本探测（`-sV`）会发送 banner 抓取请求，日志中同端口出现连续连接。
- **检测命令**：
```bash
# 看 access.log / netfilter 日志：单 IP 短时命中多个端口
grep -cE "22|80|443|3306" /var/log/iptables.log
# 防火墙统计 SYN 半连接
ss -s | grep SYN
netstat -ant | grep SYN_RECV | wc -l
# 被动检测：tcpdump 看无 ACK 的 SYN 洪泛
tcpdump -i eth0 -nn "tcp[tcpflags] & tcp-syn != 0 and tcp[tcpflags] & tcp-ack == 0" | head
```
- **拦截建议**：`fail2ban` 对同 IP 短时命中多端口自动封禁；防火墙限速同源端口扫描；赛中对已知攻击 IP 直接封禁。

## Metasploit（Meterpreter）特征

- **特征**：
  - payload 默认监听端口 4444（`windows/meterpreter/reverse_tcp`）、5555 等；stage1 为随机 TCP 载荷，stage2 无 HTTP 头。
  - stage2 流量以固定魔数开头（meterpreter 分帧头，常见 `\x00\x00\x00`），载荷大小固定且周期性交互。
  - 反弹型（reverse_tcp）从受害机主动连攻击机；绑定型（bind_tcp）在受害机开端口。
  - msf 的 HTTP 通道（`reverse_http/reverse_https`）流量含 `MZ...` 载荷随机化，UA 常见 `Mozilla/4.0 (compatible; MSIE 6.0...)`。
- **检测命令**：
```bash
# 出站 4444/5555 端口连接（业务几乎用不到）
ss -antp | grep -E ":4444|:5555"
# 抓包看原始 TCP 负载的固定帧头与周期性
tcpdump -i eth0 -n host <attacker_ip> and port 4444
# 受害机侧：进程与主机名混淆的 svchost/随机名进程外连
```
- **拦截建议**：出站策略封禁非业务端口（仅放行 53/80/443/业务）；对开放端口的主机重点审计外连。

## Cobalt Strike Beacon 特征

- **特征**（与 16 号文件呼应，此处给检测/拦截落地）：
  - 心跳固定间隔（默认 60s），请求/响应大小恒定；UA 固定。
  - DNS Beacon：高熵子域 TXT 查询（`<hex>.<domain>`），TXT 记录短时间激增。
  - HTTPS Beacon：TLS JA3 指纹已知（`1dac2f4553d5f4e52fbc26d2eec1abef` 等已知恶意值）；证书自签名或 CN 随机。
- **检测命令**：
```bash
# Suricata/Zeek 规则：固定 UA + /__utm.gif|/pixel.gif 路径
# 用 zeek 提取 ssl.log 查 ja3
zeek -r capture.pcap
cat ssl.log | awk -F'\t' '{print $10, $8}'   # 按 JA3 排序列出
# DNS 高熵子域：统计查询名长度与字符集
tshark -r capture.pcap -Y "dns.qry.name contains \"attacker.com\"" -T fields -e dns.qry.name | head
```
- **拦截建议**：对已知恶意 JA3 建黑名单；封禁动态域名（freenom/duckdns 段）；对 DNS TXT 记录做长度与频率告警。

## sqlmap 请求特征

- **特征**：
  - 默认 UA：`sqlmap/1.8.x#stable (https://sqlmap.org)`（可改，但默认常见）。
  - 请求头注入顺序固定：`Host` → `Cache-Control: no-cache` → `Pragma: no-cache` → `User-Agent` → `Accept: */*` → `Accept-Encoding: gzip, deflate` → `Connection: close`。
  - 请求参数中出现 `%0a`、`-1'`、`1/1`、`1-1`、`if(now()=sysdate(),sleep(0),0)` 等探测痕迹；同一 URL 被带大量不同 payload 的 GET/POST 反复请求。
  - 默认线程/延迟特征：请求节奏规律（间隔或突发）。
- **检测命令**：
```bash
grep -iE "sqlmap|no-cache" /var/log/nginx/access.log | head
grep -E "sleep\(0\)|if\(now|1-1|1/1" /var/log/nginx/access.log | head
```
- **拦截建议**：WAF 规则库内置 sqlmap UA 黑名单；对同一 URL 同 IP 的高频注入特征请求限速；封禁短时大量 4xx/5xx 的 IP。

## Burp Suite Repeater 特征

- **特征**：
  - UA 默认不发送（或继承浏览器复制来的 UA，无统一特征）。
  - Repeater 无 `Accept-Encoding`、无 `Referer`、头部顺序与浏览器差异明显；常只保留 `Host` + `User-Agent` + `Content-Type`。
  - 请求无 Cookie 或 Cookie 异常，但手动构造 header（如加 `X-Forwarded-For` 混淆）。
  - 特点：同一连接内连续请求、参数被人工改动（大小写/编码变化）。
- **检测命令**：主要靠**行为**而非特征：单 IP 对单 URL 的请求参数高频变异、无浏览器指纹（无 JS/CSS/图片资源请求）。
- **拦截建议**：对"只有主文档请求、无静态资源跟随"的 IP 单独关注；对关键接口加请求频率与参数一致性校验。

## 冰蝎 / 哥斯拉 / 蚁剑 流量特征汇总

| 工具 | 默认 UA / Header | 流量特征 | 日志关键字 |
|------|------------------|---------|-----------|
| 冰蝎 Behinder | 常规 Chrome UA（Java 发），无真实浏览器细节 | AES 加密、响应长度恒定、默认密钥 md5(rebeyond) | 响应字节数恒定、高熵 body |
| 哥斯拉 Godzilla | 带 `Accept-Encoding: gzip, deflate`，偶带 `rememberMe=deleteMe` | 响应首字节 `d`、含 Java 序列化 `aced0005` | 参数名 `pass`、POST 到 .jsp/.php |
| 蚁剑 AntSword | 旧版 `antSword/v2.1`；新版 `Mozilla/5.0 (compatible; MSIE 10.0...)` | `@eval(base64_decode(`、`assert(base64_decode(`、请求参数 `xxx0=...&xxx1=` | `antSword`、`eval(base64` |

- **检测命令（落地）**：
```bash
# 1) UA 匹配
grep -iE "antSword|Behinder|Godzilla" /var/log/nginx/access.log
# 2) 响应长度恒定（多次 POST 同文件同长度）
awk '{print $7, $9, $10}' /var/log/nginx/access.log | sort | uniq -c | awk '$1>3' | sort -rn | head -20
# 3) 高熵参数（Python 一行：统计请求参数熵）
# 4) 序列化特征
grep -a "aced0005" /var/log/nginx/access.log
```
- **拦截建议**：对含 `eval(base64_decode|assert(base64_decode` 的参数直接拒绝；对同文件响应长度恒定且 body 高熵的会话封源 IP；上传目录禁止执行。

## 常见扫描 UA 列表

| UA 片段 | 对应工具 | 拦截方式 |
|---------|---------|---------|
| `sqlmap/` | sqlmap | WAF 黑名单 |
| `Nikto` | Nikto 扫描器 | WAF 黑名单 |
| `WPScan` | WPScan | WAF 黑名单 |
| `zgrab` | zgrab 扫描器 | WAF 黑名单 |
| `masscan` | masscan | 防火墙限速 |
| `python-requests` | 各类 python 脚本 | 行为分析 |
| `curl/`（无浏览上下文） | curl 手工利用 | 行为分析 |
| `Go-http-client` | Go 工具（常见 fscan/代理） | 行为分析 |

- **落地命令（fail2ban 示例，过滤恶意 UA 后封 IP）**：
```bash
# /etc/fail2ban/filter.d/badua.conf
[Definition]
failregex = .*"User-Agent: (sqlmap|Nikto|WPScan|masscan).*
# jail.local 引用并 ban 600s
# 更彻底：nginx 层直接 403
if ($http_user_agent ~* "sqlmap|Nikto|WPScan|masscan") { return 403; }
```

## 检测与拦截综合 Checklist

- [ ] 防火墙开启 SYN 洪泛与端口扫描限速，`ss -s` 观察 SYN_RECV
- [ ] fail2ban 配置：SSH 爆破、恶意 UA、高频注入三类规则
- [ ] 出站防火墙仅放行业务端口，阻断 4444/5555/7000 等 C2 常见端口
- [ ] 每日对 access.log 跑一遍 UA + 响应长度恒定 + 高熵参数三个脚本
- [ ] WAF 规则覆盖：sqlmap UA、`eval(base64_decode`、`%{`、`${jndi:`、`union select`
- [ ] 命中即封 IP（持续至赛期结束），并记录到溯源报告
