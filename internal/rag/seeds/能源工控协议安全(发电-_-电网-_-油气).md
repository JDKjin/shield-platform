# 能源工控协议安全（发电 / 电网 / 油气）

## 常见工控协议与端口
- Modbus TCP：502，功能码读 01/02/03/04，写 05/06/15/16；无原生认证
- IEC 60870-5-104（IEC104）：2404，用于电网远动，无强认证
- DNP3：20000，SCADA 常用，支持写操作
- OPC UA：4840，现代工控互通，支持账号认证（常被弱口令）
- S7（西门子）：102，PLC 编程与数据访问
- MQTT：1883/8883，物联网遥测，常匿名

## 协议层风险：Modbus 写线圈 / 未授权读写 / 重放
- 未授权读写：直接发送写功能码修改线圈/寄存器（启停设备、篡改遥测）
- 重放攻击：重放历史控制指令
- 中间人：明文协议可被窃听/篡改
- 默认/弱口令：OPC UA、HMI、网关管理后台

## 加固与防护建议
- 网络隔离：工控网与生产网/办公网分段，VLAN + ACL
- 协议白名单：防火墙仅放行必要的功能码与地址区间
- 关闭不必要的写权限；对关键控制指令启用双人复核/硬件联锁
- 修改默认口令、启用 OPC UA 认证与加密
- 部署工控 IDS（如利用 Suricata 的 modbus/iec104 规则）检测异常写操作
- 监控遥测突变：同一遥测点短时间内大幅跳变、批量写操作

## 本题防御重点
能源综合防御赛的「energy_ics」规则检测的目标是：HTTP 管理接口中携带的危险工控操作（如写入线圈、下发控制指令、调用停止/启动设备、协议端口探测），以及异常协议字段。命中后应拦截并记录，便于溯源报告说明攻击意图。

```bash
# 读保持寄存器（FC=03），地址 0 起 10 个

# 写单个线圈（FC=05），地址 5 = ON

# 写单个寄存器（FC=06），地址 5 = 100

```

#### 2.2 pymodbus Python 脚本（批量测试，[WIN] 可运行）
```python
# modbus_test.py
from pymodbus.client import ModbusTcpClient

c = ModbusTcpClient('192.168.1.10', port=502, timeout=3)
c.connect()

# 读线圈（FC=01）
print('  coils:', c.read_coils(address=0, count=10, slave=1).bits)
# 读离散输入（FC=02）
print('   disc:', c.read_discrete_inputs(address=0, count=10, slave=1).bits)
# 读保持寄存器（FC=03）
print('     hr:', c.read_holding_registers(address=0, count=10, slave=1).registers)
# 读输入寄存器（FC=04）
print('     ir:', c.read_input_registers(address=0, count=10, slave=1).registers)
# 写单个线圈（FC=05）
print(' w coil:', c.write_coil(address=5, value=True, slave=1))
# 写单个寄存器（FC=06）
print('  w reg:', c.write_register(address=5, value=100, slave=1))
# 写多个线圈（FC=15）
print('w coils:', c.write_coils(address=10, values=[True]*8, slave=1))
# 写多个寄存器（FC=16）
print(' w regs:', c.write_registers(address=10, values=[1,2,3], slave=1))

c.close()
```

运行：
```bash

```

### 5. Suricata 加载工控规则启动命令（CLI 路径）

#### 5.1 安装
```bash
# CentOS 7
yum install -y epel-release && yum install -y suricata

apt install -y suricata
```

#### 5.2 启动加载工控规则
```bash
# 假设规则文件位于 /etc/suricata/rules/ics.rules
# suricata.yaml 中确保：
#   default-rule-path: /etc/suricata/rules
#   classification-file: /etc/suricata/classification.config
#   reference-config-file: /etc/suricata/reference.config

# 前台启动加载工控规则
suricata -c /etc/suricata/suricata.yaml -i eth0 \
  --set classification-file=/etc/suricata/classification.config \
  --set default-rule-path=/etc/suricata/rules \
  --set rule-files=ics.rules \
  -l /var/log/suricata/

# 后台守护方式
suricata -c /etc/suricata/suricata.yaml -i eth0 -D
```

#### 5.3 工控规则示例（写入 /etc/suricata/rules/ics.rules）
```
alert tcp any any -> any 502 (msg:"Modbus write coil"; content:"|00 00 00 00 00 06|"; depth:6; byte_test:1,==,5,6; sid:100001; rev:1;)
alert tcp any any -> any 2404 (msg:"IEC104 control command"; content:"|68|"; depth:1; sid:100002; rev:1;)
alert tcp any any -> any 102 (msg:"S7comm write var"; sid:100003; rev:1;)
```

### 6. iptables / firewalld 限制工控端口白名单

#### 6.1 iptables（CentOS 7 / Ubuntu 20.04 通用）
```bash
# 仅允许 192.168.10.0/24（工控运维段）访问 502 Modbus
iptables -A INPUT -p tcp --dport 502 -s 192.168.10.0/24 -j ACCEPT
iptables -A INPUT -p tcp --dport 502 -j DROP

# 102 S7comm
iptables -A INPUT -p tcp --dport 102 -s 192.168.10.0/24 -j ACCEPT
iptables -A INPUT -p tcp --dport 102 -j DROP

# 2404 IEC104
iptables -A INPUT -p tcp --dport 2404 -s 192.168.10.0/24 -j ACCEPT
iptables -A INPUT -p tcp --dport 2404 -j DROP

# 4840 OPC UA
iptables -A INPUT -p tcp --dport 4840 -s 192.168.10.0/24 -j ACCEPT
iptables -A INPUT -p tcp --dport 4840 -j DROP

# 20000 DNP3
iptables -A INPUT -p tcp --dport 20000 -s 192.168.10.0/24 -j ACCEPT
iptables -A INPUT -p tcp --dport 20000 -j DROP

# 保存规则
service iptables save                      # CentOS 6/7
iptables-save > /etc/iptables/rules.v4     # Ubuntu
```

#### 6.2 firewalld（CentOS 7 推荐）
```bash
# 启动
systemctl enable --now firewalld

# 限制 502 仅运维段
firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="192.168.10.0/24" port port="502" protocol="tcp" accept'
firewall-cmd --permanent --add-rich-rule='rule family="ipv4" port port="502" protocol="tcp" drop'

# 批量处理 102 2404 4840 20000
for p in 102 2404 4840 20000; do
  firewall-cmd --permanent --add-rich-rule="rule family=\"ipv4\" source address=\"192.168.10.0/24\" port port=\"$p\" protocol=\"tcp\" accept"
  firewall-cmd --permanent --add-rich-rule="rule family=\"ipv4\" port port=\"$p\" protocol=\"tcp\" drop"
done

# 重载生效
firewall-cmd --reload
```

### 8. tshark 提取工控协议数据（CLI 路径，[WIN] 可运行）

#### 8.1 安装
```bash
# CentOS 7
yum install -y wireshark
# Ubuntu 20.04
apt install -y tshark
```

#### 8.2 提取字段
```bash
# Modbus 功能码、参考号、寄存器值
tshark -r modbus.pcap -Y modbus -T fields \
  -e frame.time -e ip.src -e ip.dst -e modbus.func_code \
  -e modbus.reference_num -e modbus.regval_uint16

# S7comm 参数功能与子功能
tshark -r s7.pcap -Y s7comm -T fields \
  -e frame.time -e ip.src -e ip.dst -e s7comm.param.func \
  -e s7comm.param.subfunc -e s7comm.data.returncode

# IEC 104 类型与传输原因
tshark -r iec104.pcap -Y iec60870_104 -T fields \
  -e frame.time -e ip.src -e ip.dst -e iec104.type \
  -e iec104.causetx

# OPC UA 服务
tshark -r opcua.pcap -Y opcua -T fields \
  -e frame.time -e ip.src -e ip.dst -e opcua.service

# DNP3 功能码与对象
tshark -r dnp3.pcap -Y dnp3 -T fields \
  -e frame.time -e ip.src -e ip.dst -e dnp3.fc -e dnp3.objects
```

### 9. Wireshark 工控协议解析 GUI 路径

#### 9.1 打开 pcap
1. 启动 Wireshark（GUI 工作站，[WIN] / Linux / macOS 均有版本）
2. File -> Open -> 选择 modbus.pcap / s7.pcap / iec104.pcap / opcua.pcap / dnp3.pcap
3. Wireshark 内置 Modbus / S7comm / IEC 104 / OPC UA / DNP3 解析器，打开后自动着色解析

#### 9.2 应用过滤器（在顶部 Filter 输入栏回车生效）
```
modbus                                  # 仅 Modbus
modbus.func_code == 5                   # 仅写线圈
modbus.func_code > 4                    # 所有写操作（05/06/15/16）
s7comm                                  # 仅 S7comm
s7comm.param.func == 0x05               # 仅写变量
iec60870_104                            # 仅 IEC 104
opcua                                   # 仅 OPC UA
dnp3                                    # 仅 DNP3
tcp.port == 502 && modbus.func_code > 4 # 异常写操作高亮
```

#### 9.3 导出特定字段
1. File -> Export Specified Packets -> 选择 Displayed 仅导出过滤结果
2. File -> Export Packet Dissections -> As CSV... -> 勾选字段（如 modbus.func_code、s7comm.param.func）
3. Statistics -> Conversations -> TCP 查看端到端会话统计
4. Statistics -> Protocol Hierarchy 查看协议占比

### 10. Modbus Poll / Modbus Slave GUI 工具使用步骤

#### 10.1 下载安装（[WIN] GUI 工具，官网 modbustools.com）
- Modbus Poll：作为主站（Master）发送读写请求
- Modbus Slave：作为从站（Slave）模拟 PLC 响应（用于离线测试，避免误操作真实 PLC）

#### 10.2 Modbus Poll 连接配置
1. 启动 Modbus Poll
2. Connection -> Connect... -> Connection 选择 Modbus TCP/IP
3. Serial Settings -> Server Address: 192.168.1.10，Port: 502
4. Slave ID: 1
5. Scan Rate: 1000 ms
6. Function: 03 Read Holding Registers（默认）
7. Start Address: 0，Quantity: 10
8. OK 后窗口显示读到的寄存器值（绿色表示成功）

#### 10.3 读写测试
- 读线圈：Setup -> Read/Write Definition -> Function 选 01 Read Coils -> OK
- 写单个线圈：双击某行单元格 -> 弹出 Write Coils 对话框 -> 输入地址与值（0/1） -> OK
- 写寄存器：双击某行 -> Write Registers -> 输入值 -> Send
- 批量写：按 F8 -> 选择 Function 16 Write Multiple Registers

#### 10.4 Modbus Slave 模拟从站
1. 启动 Modbus Slave
2. Connection -> Connect... -> Modbus TCP/IP，Listen Port: 502
3. Slave ID: 1
4. Setup -> Slave Definition -> Function 03，Address 0，Quantity 20
5. 在数据区直接修改值，Poll 端可读到

```bash
# tshark 解析 PN-DCP
tshark -r pn.pcap -Y profinet -T fields \
  -e frame.time -e eth.src -e eth.dst -e pn_dcp.service_id -e pn_dcp.service_type

# pn-find 扫描 Profinet DCP 设备（源码安装：https://github.com/profinet/pn-find）
git clone https://github.com/profinet/pn-find.git
cd pn-find
pip3 install -r requirements.txt
python3 pnfind.py eth0
```
