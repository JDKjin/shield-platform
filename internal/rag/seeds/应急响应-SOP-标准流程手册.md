# 应急响应 SOP 标准流程手册

> 统一的应急响应作业流程，适用于能源防御赛与日常主机告警处置。原则：**先止损、再溯源、后加固**，全程保留证据，动作可回溯。

## 一、事件分级与响应时限

| 级别 | 事件特征 | 响应时限 |
|------|---------|---------|
| P1 严重 | 核心业务被攻破、flag 被拿、勒索/挖矿、横向扩散 | 立即（0-5 分钟） |
| P2 高 | 发现 Webshell/后门、异常外连、爆破成功迹象 | 15 分钟内 |
| P3 中 | 爆破尝试、扫描探测、单次告警 | 30 分钟内研判 |
| P4 低 | 误报、正常行为告警 | 记录归档 |

## 二、标准处置六步

1. **确认**：核实告警真实性（面板告警 + 现场 `ss -tlnp`/`ps -ef`/`ls -l` 交叉确认，避免误伤业务）。
2. **止损**：封 IP、断入口、隔离文件、`kill` 进程，动作最小化影响业务。
3. **取证**：`mkdir -p /root/evidence`，复制样本/日志/配置，`stat` 记时间戳，截图存档。**取证先于清理**。
4. **溯源**：按「时间线 → 入口 → 手法 → 持久化 → 影响范围」还原攻击链，锁定攻击源。
5. **加固**：修复漏洞、清理后门、改口令、恢复配置，覆盖被利用的入口。
6. **复盘**：验证业务恢复、后门无复现，输出事件报告。

## 三、时间线模板（报告直接可用）

| 时间 | 事件 | 证据索引 | 处置动作 | 责任人 |
|------|------|---------|---------|--------|
| 10:03:12 | 爆破 192.168.1.50 命中 root | secure 日志 L1234 | 封 IP | A |
| 10:05:00 | 上传 webshell.php | access.log L890 | 隔离取证 | A |
| 10:12:00 | 删除 webshell 并加固 | evidence/ | 清后门+改口令 | B |

## 四、关键证据清单

- 系统：`last`、`grep Accepted /var/log/secure`、`ss -tlnp`、`ps -ef`、`crontab -l`、`stat` 可疑文件
- 网络：`ss -tnp` 连接、WAF 拦截日志、`tcpdump` 抓包（必要时）
- Web：access/error 日志、webshell 样本、上传时间戳、`.user.ini` 配置
- 数据库：general_log、error log、慢查询日志、`redis-cli config get` 快照
- Windows：4624/4625/4720/7045 事件（参考「Windows 事件日志」手册）

## 五、应急报告结构

1. 事件概述（发生时间、影响资产、等级）
2. 攻击研判（来源、手法、入口）
3. 攻击链溯源（访问 → 利用 → 提权 → 持久化 → 横向）
4. 处置动作与加固前后对比
5. 业务可用性验证
6. 结论与建议

## 六、常见坑

- **先清理后取证**会丢证据，取证目录放 Web 根目录外。
- 杀进程前先看父子进程，守护进程会把你清的再拉起来。
- 封 IP 前确认不是 CDN/出口 IP 误伤正常业务来源。
- 加固后必须重启受影响服务并复扫，确认后门不复发才算收敛。
